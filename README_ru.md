# RAG для документов на английском и грузинском языках

RAG-приложение для извлечения данных из PDF-документов на английском и
грузинском языках и ответов на вопросы на русском языке с опорой на
источники.

Исходные документы могут быть на английском, грузинском или содержать
оба языка. Ответы и текст промптов --- на русском языке, весь код и
документация --- на английском.

## Архитектура

Процессы индексации и обработки запросов разделены:

-   **Индексация**: `app/pipeline.py` считывает каждую страницу PDF
    (`app/pdf.py`). Если встроенный текстовый слой содержит не менее
    `MIN_TEXT_LENGTH` символов, используется этот текст независимо от
    того, на каком языке он написан --- английском или грузинском. Если
    текста меньше или он отсутствует, используется OCR с помощью
    Tesseract (`app/ocr.py`), по умолчанию настроенного на языки `kat`
    (грузинский) и `eng` (английский). Tesseract распознаёт оба языка
    одновременно, в том числе на страницах со смешанным текстом;
    приложение не определяет язык каждой страницы и не выбирает язык OCR
    динамически. Извлечённый текст нормализуется (`app/text.py`),
    разбивается на фрагменты по количеству символов (`app/chunking.py`),
    сохраняется в SQLite (`app/models.py`, `app/repositories.py`) и
    индексируется в Qdrant (`app/indexing.py`, `app/qdrant_store.py`).
-   **Обработка запросов**: `app/rag.py` преобразует вопрос в эмбеддинг
    (`app/embeddings.py`), выполняет поиск в Qdrant
    (`app/retrieval.py`), проверяет найденные фрагменты и оборачивает их
    в блоки недоверенных источников с локальными для запроса
    идентификаторами (`app/context.py`), после чего обращается к
    настроенному LLM-провайдеру за ответом на русском языке с цитатами
    вида `[стр. N]` (`app/answer.py`, `app/llm.py`). Инструкции промпта
    версионируются и отделены от доказательной базы, если провайдер
    поддерживает раздельные сообщения. По умолчанию используется
    OpenRouter; Ollama можно выбрать явно.

Внешние сервисы подключаются через абстрактные интерфейсы
(`EmbeddingService`, `VectorStore`, `OCRProcessor`, `LLMService`) и
создаются один раз на процесс в `app/dependencies.py`.

Проект предоставляет как инструменты командной строки в `main.py`, так и
веб-интерфейс с серверным рендерингом на FastAPI и Jinja2. Интерфейс
повторно использует существующие сервисы индексации и RAG, сохраняя
возможность работы через CLI.

## Локальная настройка

1.  Установите зависимости:

    ``` powershell
    .\venv\Scripts\python.exe -m pip install -r requirements.txt
    ```

2.  Скопируйте `.env.example` в `.env` и при необходимости измените URL
    сервисов или названия моделей. Для удалённого экземпляра Qdrant
    укажите его адрес в `QDRANT_URL`, а если экземпляр требует
    аутентификации --- задайте `QDRANT_API_KEY`. Храните API-ключ в
    `.env` или другом хранилище секретов; не добавляйте его в Git.

3.  Запустите Qdrant и настройте выбранного LLM-провайдера. Для
    провайдера OpenRouter, используемого по умолчанию, требуется
    `OPENROUTER_API_KEY`. Чтобы использовать Ollama, задайте
    `LLM_PROVIDER=ollama`, запустите Ollama и установите настроенную
    модель. Для распознавания сканов на грузинском и английском языках
    установите языковые данные Tesseract для `kat` и `eng`.

4.  Примените миграции:

    ``` powershell
    .\venv\Scripts\alembic.exe upgrade head
    ```

5.  Перед индексацией проверьте все зависимости времени выполнения,
    включая схему базы данных:

    ``` powershell
    .\venv\Scripts\python.exe main.py preflight
    ```

6.  Проиндексируйте документ:

    ``` powershell
    .\venv\Scripts\python.exe main.py index data\input\georgian_scan.pdf
    ```

Повторный запуск `index` для того же файла не требует больших затрат:
страницы, содержимое которых не изменилось согласно хешу, пропускаются,
поэтому OCR для них не выполняется повторно. Если PDF содержит пригодный
для использования текстовый слой, текст извлекается напрямую. Для
отсканированных страниц или страниц, где встроенный текст содержит
меньше `MIN_TEXT_LENGTH` символов, используется OCR. При этом длинный,
но некачественный или искажённый текстовый слой может пройти текущую
проверку длины и поэтому не попасть на OCR.

## Веб-интерфейс

Установите зависимости проекта, примените миграции и убедитесь, что
Qdrant, выбранный LLM-провайдер и Tesseract настроены. Запустите
интерфейс, привязав его к loopback-интерфейсу:

``` powershell
.\venv\Scripts\python.exe -m uvicorn app.web:app --host 127.0.0.1 --port 8000
```

Откройте <http://127.0.0.1:8000/> в браузере. Не меняйте адрес хоста на
`0.0.0.0`: в первой версии нет аутентификации пользователей, и
приложение предназначено только для локального доступа. Запросы к
формам, изменяющим состояние приложения, отклоняются, если заголовок
`Origin` не соответствует ожидаемому источнику.

Интерфейс предоставляет следующие маршруты:

-   `/` --- обзорная страница.
-   `/documents` --- записи, хранящиеся в SQLite. Эта страница не
    проверяет наличие соответствующих векторов в Qdrant. Ссылка с именем
    файла открывает исходный PDF, если он доступен в `data/documents/`
    или найден как соответствующий файл в `data/input/`. Также каждый
    документ можно удалить вместе со страницами, фрагментами и векторами
    в Qdrant.
-   `/upload` --- загрузка PDF и индексация через существующий конвейер
    обработки документов. Файл должен иметь расширение `.pdf` и
    корректную сигнатуру PDF; максимальный размер --- 50 МиБ.
-   `/ask` --- отправка вопроса в существующий RAG-конвейер и
    отображение ответа на русском языке. Можно выбрать один или
    несколько документов, чтобы ограничить область поиска. Если
    документы не выбраны, поиск выполняется по всем документам.
-   `/health` --- проверка работоспособности веб-процесса; она не
    заменяет `main.py preflight`.

Загружаемые файлы передаются потоком во временный файл, индексируются, а
затем сохраняются по пути `data/documents/<sha256>.pdf`; имя, переданное
пользователем, никогда не используется в качестве пути к каталогу.
Сохранённые оригиналы доступны для просмотра непосредственно на
локальной странице `/documents`. Документы, ранее проиндексированные
через CLI, также могут содержать ссылку на соответствующий PDF в
`data/input/`; перед выдачей файла проверяется его SHA-256. Для
документов, проиндексированных из других мест, исходный путь не
сохраняется. Чтобы сделать оригинал доступным через интерфейс, такой
документ необходимо загрузить через UI. Удаление документа удаляет его
записи в SQLite, соответствующие векторы в Qdrant и загруженный оригинал
с именем на основе хеша. Совпадающие файлы в `data/input/` сохраняются.
Страница ответа отображает строку ответа, полученную от RAG, и
самостоятельно не восстанавливает ссылки на источники.

Ответы представляются обычным русским текстом с указанием страниц в
формате `[стр. N]`. Приложение проверяет, что номера процитированных
страниц присутствуют среди найденных результатов и что в каждом
обнаруженном предложении есть цитата. Эта проверка на принадлежность не
доказывает, что источник фактически подтверждает соответствующее
утверждение.

Обработка вопросов LLM выполняется синхронно: ответ `/ask` ожидает
завершения поиска, работы провайдера и проверки ответа. Приложение не
сохраняет вопросы, промпты, извлечённый текст, ответы или исходные
ответы провайдера. При этом выбранный провайдер получает содержимое
запроса и применяет собственные условия хранения и обработки данных.
Версия промпта указана в `app/answer.py` (`answer-v3`). Модель получает
запрос на генерацию обычного текста, а не данных по фиксированной
JSON-схеме, поскольку автоматический выбор модели в OpenRouter может
возвращать разные форматы. Пустой ответ, отсутствие цитат страниц и
ссылки на страницы, отсутствующие в найденных результатах, отклоняются.
Это не проверяет фактическую обоснованность ответа и не гарантирует, что
каждая цитата действительно подтверждает предложение, к которому она
относится.

Параметры `OPENROUTER_SUPPORTS_STRUCTURED_OUTPUT` и
`OPENROUTER_SUPPORTS_JSON_MODE` описывают возможности настроенного
провайдера. Текущий конвейер формирования ответов запрашивает обычный
текст и не передаёт схему ответа.

При изменении `EMBEDDING_MODEL` или `EMBEDDING_SIZE` необходимы
совместимая коллекция Qdrant и повторная индексация всех документов.
`QdrantVectorStore` отказывается запускаться, если размерность векторов
или тип расстояния в коллекции не соответствуют настройкам. Поэтому
несоответствие обнаруживается при запуске, а не во время индексации.

При запуске приложение также создаёт индексы payload по ключевым словам
для `document_id` и `page_id`. Они необходимы для фильтрации результатов
поиска и очистки устаревших векторов.

## Миграции

Изменения схемы базы данных выполняются через Alembic;
`Base.metadata.create_all()` никогда не используется для изменения схемы
в production.

``` powershell
.\venv\Scripts\alembic.exe upgrade head
.\venv\Scripts\alembic.exe downgrade base
.\venv\Scripts\alembic.exe current
```

Начальная ревизия идемпотентна: она проверяет существующие таблицы и
индексы, поэтому может обновить старую базу `data/app.db`, созданную до
появления `document_chunks` и уникального ограничения
`(document_id, page_number)`.

## Тесты

``` powershell
.\venv\Scripts\python.exe -m pytest -m "not integration"
.\venv\Scripts\python.exe -m pytest -m integration
```

Для стандартного набора тестов не требуются Qdrant, Ollama, Tesseract
или загрузка модели: используются SQLite в памяти,
`QdrantClient(":memory:")` и имитации зависимостей. Тесты с маркером
`integration` требуют запущенный Ollama с настроенной моделью и
корректно пропускаются, если он недоступен.

Веб-маршруты покрыты тестами в `tests/test_web.py`. Запустить их можно
командой:

``` powershell
.\venv\Scripts\python.exe -m pytest tests\test_web.py
```

Два теста в `test_embeddings.py`, которые загружают настоящую модель
`BAAI/bge-m3`, запускаются только при явном включении через
`RUN_REAL_MODEL_TESTS=1`. Загрузка этой модели в Windows может аварийно
завершить интерпретатор с ошибкой
`Windows fatal exception: access violation` внутри `torch`. Это
критическое падение, а не исключение Python, поэтому такие тесты должны
пропускаться до обращения к модели:

``` powershell
$env:RUN_REAL_MODEL_TESTS = "1"
.\venv\Scripts\python.exe -m pytest -m integration
```

Проверка стиля и форматирования:

``` powershell
.\venv\Scripts\python.exe -m ruff check .
.\venv\Scripts\python.exe -m black --check .
```

## Эксплуатационные примечания

-   SQLite и Qdrant не обновляются атомарно. При индексации сначала
    записываются новые фрагменты и векторы, и только после успешного
    завершения индексации удаляются предыдущие записи фрагментов. При
    ошибке транзакция откатывается, а предыдущие векторы
    восстанавливаются.
-   `main.py preflight` проверяет схему базы данных, Qdrant,
    конфигурацию выбранного LLM-провайдера и языковые данные Tesseract.
    Для Ollama проверяется настроенная модель; для OpenRouter
    проверяется наличие API-ключа без отправки реального запроса,
    который мог бы повлечь оплату.
-   Запросы к OpenRouter могут повлечь расходы у провайдера. Приложение
    никогда не переключает провайдеров или модели автоматически.
    Предварительная проверка подтверждает только наличие API-ключа, но
    не проверяет, действителен ли он и есть ли на счёте средства.
-   Повторные вызовы LLM выполняются только после безопасных ошибок на
    этапе установления соединения и ответов HTTP 429, в пределах
    ограничений на количество попыток и общее время выполнения. Если
    заголовок `Retry-After` содержит корректное значение, оно
    учитывается. Тайм-ауты чтения/записи, потеря соединения после
    передачи запроса, другие HTTP-статусы и ошибки проверки ответа не
    приводят к повторной попытке. Неизвестный результат запроса может
    означать, что провайдер уже обработал его.
-   `/ask` преобразует типизированные ошибки провайдера в безопасные
    рекомендации на русском языке и записывает в журнал провайдера,
    модель, категорию ошибки, количество попыток, затраченное время и
    идентификатор запроса провайдера, если он доступен. API-ключ,
    вопрос, извлечённый текст, промпт и ответ модели в журнал не
    записываются.

Реальный smoke-тест OpenRouter по умолчанию отключён. Его запуск может
повлечь расходы. Выполняйте его только при настроенном ключе OpenRouter
и если вы явно хотите отправить реальный запрос провайдеру:

``` powershell
$env:RUN_OPENROUTER_TESTS = "1"
.\venv\Scripts\python.exe -m pytest tests\test_rag_integration.py -m integration -k openrouter
Remove-Item Env:RUN_OPENROUTER_TESTS
```
